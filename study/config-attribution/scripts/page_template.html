What stands out

  • TP2 doesn't fit
    The 70B weights leave two H100s little room for KV cache. The batch caps at about 44 requests and roughly 615 of 800 requests are preempted and recomputed, so TTFT is tens of seconds of waiting at every load. The breakdown shows the symptom (waiting, preemption), and the capped batch size points to the cause (KV capacity).
  • ITL is mostly weight reads
    At TP4 and TP8, reading the weights is 60–80% of each decode step. TP halves that per step, which is why ITL nearly halves from TP4 to TP8. Fixed per-step overhead (about 3 ms) does not shrink with TP, so its share grows at TP8.
  • TTFT is mostly fixed API overhead
    Below saturation, about 15.6 ms of TTFT is a fixed per-request API cost, and the prompt step itself is small (chatbot prompts are short). Once TP4 saturates (48 req/s and up), its TTFT becomes almost entirely waiting for a batch slot, while TP8 still has headroom.
  • Cost per token tracks batch size
    Weight reads dominate GPU time per token. TP8 runs smaller batches at the same load, so each weight read is shared by fewer tokens and it costs more per token. The gap narrows as load rises and batches fill.

How to read this, and its limits

  • This is the breakdown as BLIS models it, not a GPU measurement. "Weight reads" means BLIS's bytes ÷ bandwidth × a learned correction. It shows where the model thinks time goes.
  • Decode compute shows as roughly zero. BLIS's trained-physics model currently prices decode compute at zero (issue #1123), so large-batch decode likely understates compute.
  • A step's full time is charged to every request in it, since that is the wall-clock time each one experiences. A request's prefill step therefore also contains other requests' decode work.
  • "Waiting for a batch slot" and "Preemption" are the time a request spends outside any step that includes it. Where nothing is preempted, the waiting piece matches BLIS's independent scheduling-delay metric.
  • API overhead is BLIS's three fixed constants: 15.6 ms per request on arrival, 0.78 ms at completion, and 0.046 ms per output token.
